# Заметки на потом: безопасность и выпуск

Это пометки для себя, в README они пока не вынесены.

## menu.yaml умеет запускать что угодно

Что есть сейчас: `run`, `open`, `steps` запускают любые программы и ссылки от имени пользователя, `admin: true` открывает запрос UAC. Файл лежит в `%APPDATA%\RadialMenu\menu.yaml`, права обычные (пишет только пользователь и программы от его имени).

Риск: если кто-то подменит файл (вредоносная программа, общий профиль, скачанный чужой `menu.yaml`), кнопка меню выполнит чужую команду, а с `admin: true` — с повышением прав после согласия в UAC.

Что можно сделать позже, от простого к сложному:
1. Описать это в README: не брать чужой `menu.yaml` не читая; `admin: true` — только для своих программ.
2. При запуске и перечитывании проверять права на файл и папку и предупреждать, если писать в них могут другие пользователи (`GetNamedSecurityInfoW`).
3. «Доверенный» хэш: после правки файла не из окна настроек показать один раз список команд (`run`/`open`/`admin`) и попросить подтверждения; хэш подтверждённого файла хранить в `config.txt`.
4. Для `admin: true` дополнительно показывать полный путь программы в подтверждении.

## Выпуск и доверие к exe

- Программа ставит глобальные хуки и эмулирует клавиши — антивирусы и SmartScreen могут ругаться на неподписанный exe. Нужны цифровая подпись (сертификат Authenticode) и отправка файла в Microsoft и вендорам антивирусов как ложное срабатывание.
- Автообновления нет: обновление — запуск нового установщика поверх (тот же AppId). Если понадобится «Проверить обновления» — смотреть последний релиз на GitHub и предлагать скачать установщик (проверять SHA256SUMS.txt).
- Проверить установщик вручную после первого релиза: установка без прав администратора, галка автозапуска, обновление поверх, удаление (автозапуск снимается, `%APPDATA%\RadialMenu` остаётся).
